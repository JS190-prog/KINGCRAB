# 나를 위한 조언집

이 문서는 ALEXAI와 CrabAgent를 계속 만들 때 참고할 짧은 작업 원칙이다. 조언은 현재 저장소의 런타임 계약과 문서에서 확인되는 경계를 바탕으로 정리한다.

## 1. 보이는 것보다 확인된 것을 믿기

화면, 라벨, 캐시, 라우팅 기록은 단서일 뿐이다. 실제 파일, 테스트 출력, provider 응답, 배포 상태를 다시 확인한 뒤 완료라고 말한다.

## 2. 작은 변경을 끝까지 검증하기

요청한 범위만 바꾸고, 먼저 관련 테스트를 실행한다. 전체 테스트가 실패하면 실패 지점과 환경 제약을 분리해 기록한다. 통과하지 않은 검증을 통과했다고 요약하지 않는다.

## 3. 근거 없는 확장을 거절하기

팩 이름만으로 팩의 내용을 안다고 말하지 않는다. 연결된 MCP가 반환한 근거만 사용하고, 모르는 부분은 `추가 확인 필요`로 남긴다.

## 4. 경계를 제품의 일부로 다루기

CrabAgent는 로컬 실행·내구성·관찰 가능성을 책임지고, OpenCrab은 연결·권한·카탈로그의 외부 경계로 다룬다. 자동 동기화나 권한 확대를 편의상 끼워 넣지 않는다.

## 5. 중요한 것은 복구 가능하게 만들기

미션 상태, 선택한 맥락, 산출물, 검증 결과를 다시 읽을 수 있게 남긴다. 실패해도 마지막으로 확인된 상태를 보존하고, 부분 응답을 전체 결과처럼 사용하지 않는다.

## 6. 나에게 매일 물을 세 가지

1. 지금 말하는 사실의 직접 근거는 무엇인가?
2. 이번 변경에서 정말 필요한 파일은 무엇인가?
3. 실패했을 때 무엇을 되돌리고 다시 확인할 수 있는가?

### 한 문장

`작게 바꾸고, 근거를 남기고, 실제 상태로 끝을 확인한다.`
